# D296: original room archive decoded offline

2026-09-21. This advances data preparation; the last target replay remains D295.
No new Dreamcast rendering, room-init or gameplay acceptance is claimed.

`st1/r120.das` was missing from the private extraction, not from the user's disc.
The existing `tools/extract_orig.py` Gcm reader located it (1,569,888 bytes).
Source file SHA-256: `97fbcf085571a687beadc5ba7239d610a313dccdc58c408246d6a31ae36717fb`.
It is now at `/root/re4data/st1/r120.das`; the mirror was refreshed. Its type-0
payload is YZ2 compressed; copying it does not convert the structures inside it.

`src/game/read.cpp` ReadAreaData calls Yz2DecodeSet/Exec, but the recovered-game
platform/misc.cpp still has a missing-function stub for yz2Decode_Decode.
Running that stub cannot yield a valid room. The new offline helper
`port/dreamcast/tools/decode_yz2.py` compiles the recovered setup and original
PowerPC assembly and runs them with qemu-ppc. It does not add emulation to the
Dreamcast. Native runtime integration of the resulting archive is still pending.

Dependencies used: Ubuntu qemu-user 8.2.2 (package
1:8.2.2+ds-0ubuntu1.18), gcc-powerpc-linux-gnu 13.3.0
(13.3.0-6ubuntu2~24.04.1). These are external build tools, not vendored code.
The helper takes a trusted payload including its ASCII header, not the DVD
container. It rejects invalid/truncated size headers, limits output to 32 MiB,
uses a temporary build directory, and bounds subprocess runtime. It is not a
sandbox for hostile archives. It refuses to overwrite an output through its CLI.

## Next implementation boundary

Extend the existing mirror/build path to consume decoded room data and expose a
versioned native loading contract. Avoid keeping both compressed and decoded
copies resident on Dreamcast. ReadAreaData's source allocation/ownership and
room restart semantics must remain valid; do not simply feed an uncompressed
file to Yz2DecodeSet or copy raw big-endian payloads into native structs.

The decoded r120 archive contains CAM, two LIT blocks, SMD, SHD, EFF, CNS, SAT,
EAT, SMX, FSE, MDT, TEX. Existing mirror reports only partial EFF support (sst
still raw), MDT handled, and the remaining formats unhandled. Work from the
actual consumers: ReadAreaData resolves archive pointers, then gameRoomInit
uses CNS and SMD/SMX before model allocations and lighting. Convert and verify
these dependencies in order. Preserve source model identity and geometry.

In parallel with this dependency sequence, the authorized cinematic skip needs
a source completion contract for r120 -> r100. r120 is not a playable-room count.
Do not spend the playable-room budget recreating cinematic presentation, but do
not bypass event side effects to hide a missing room loader. Main menu rendering,
GX/audio integration and the existing performance/residency backlogs remain open.
